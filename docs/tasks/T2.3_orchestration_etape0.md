## Plan d'implémentation

### Sous-tâches
1. **`acquire(config, root, conn, journal=DEFAULT_REJECTION_LOG, ocr_convert=None) -> list[AcquisitionResult]`** dans `pipeline.py` :
   - itère `iter_allowed_files(root, config.perimeter)` (T1.4) ;
   - applique `run_step0_checks` (T1.4) : non accepté → déjà journalisé, on saute ;
   - dispatch selon la route : `direct_read` → `read_direct(path)` (T2.1) ; `ocr` → `ocr_convert(path)` (paramètre injectable, défaut `ocr.convert` de T2.2) ; toute autre route → rejet journalisé `unknown_route` ;
   - `ValueError` levée par une voie de conversion → rejet journalisé `conversion_failed` (`log_rejection`), on poursuit le lot : un fichier en échec n'arrête pas le parcours.
2. **`chunk_text(text, max_chars=DEFAULT_CHUNK_CHARS) -> list[str]`** : découpage des documents longs (`conception.md` §4), préférence aux frontières de paragraphes (`\n\n`), découpage « en dur » d'un paragraphe dépassant `max_chars`. Livré ici et testé ici ; appliqué à l'étape 2 (analysis) — le contrat `AcquisitionResult` conserve le texte intégral, persisté dans `conversion`.
3. **`run_step0(config_dir, base) -> list[AcquisitionResult]`** : charge la configuration (`load_config`), `init_db(base)` (idempotent), itère toutes les `allowed_roots` du périmètre et agrège les résultats d'`acquire`. Le squelette `run(config_dir, root) -> list[WriteResult]` est **conservé tel quel** (contrat vérifié par `test_contracts.py::test_stub_signatures_reference_the_contracts`) pour les étapes 1-7 des EPIC suivantes.
